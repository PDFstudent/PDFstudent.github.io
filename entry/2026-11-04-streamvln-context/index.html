具身智能 · 2026-11-04

StreamVLN：32 步窗口、历史帧与 KV 缓存怎样配合

从连续导航例子区分窗口内追加、边界重建和论文中的记忆压缩，避免把分块重置理解成逐帧滑窗。

VLN数据验证

机器人走过一个路口后，模型既要利用过去的画面，又不能让上下文无限增长。StreamVLN 的关键问题因此不是“有没有记忆”，而是哪些画面进入当前上下文、哪些计算可以复用，以及窗口结束时究竟清除了什么。原讨论连续追问了网络结构、完整例子、KV 缓存和 32 到 64 步的变化，本篇将它们接成同一条执行链。

图像怎样变成导航动作

视觉编码、语言主干与离散动作

原讨论描述的模型路线为 SigLIP 图像编码器、视觉投影器和 Qwen2 系列语言主干，采用视频多模态模型接口。图像先变成视觉特征，再映射到语言模型可接收的表示，与指令、历史信息和动作上下文共同参与生成。模型规模与骨干名字应绑定具体配置，不能把某个 7B 配置当成所有版本的定义。

输出通过语言模型词表头生成导航动作表示，再解析成前进、左转、右转或 STOP。这里并不是另外接一个连续轨迹扩散头。假设一次生成四个动作、每次前进 25 厘米或转向 15 度，可以演示“看图—生成动作块—执行—再看图”；这些数值用于说明流程，不是本轮机器人测试结果，也不意味着任意机器人都支持这组动作。

动作块让观测与执行频率不同

模型生成一个动作块后，环境可以连续执行其中的动作，直至需要下一次规划。环境步数、视觉帧数、语言生成次数因此不能混用。若提前生成 STOP，或解析后的动作数量不同，“32 步一定调用八次模型”就不成立；它只在每块恰好执行四步的简化例子中成立。

KV 缓存到底省掉什么

同一窗口内保留已计算前缀

自回归注意力中，旧 token 的键和值可以保存在 past_key_values。下一次追加视觉和文本内容时，模型利用旧前缀缓存，而不必从头计算每个旧 token 的 K、V。新图像编码、新 token 的投影以及它们与历史上下文的注意力仍需要计算，缓存并没有让后续推理变成零成本。

示意地，若当前 token 数为 n，新增 m 个 token，缓存减少的是反复处理旧前缀的工作；新查询仍需关注允许访问的历史键值。具体算子复杂度、显存和加速比例由模型与实现决定，不能从“用了 KV”直接推出固定倍数。

到达窗口边界不是把旧 KV 原样带过去

2026 年 11 月 5 日核对的公开评测入口中，默认参数包含 num_frames=32、num_history=8 和四步未来动作；执行到边界时重置模型相关上下文、输出序列与 past_key_values，下一段重新选择历史图像。这个路径支持“窗口内复用、窗口间重建”的判断，不能据此声称旧 KV 跨窗口原样保留。

这里的 32 在该执行路径中参与环境步计数边界判断，不能仅凭参数名理解为 32 次模型调用。代码分支与参数都可能变化，本文解释的是此次读取到的实现。

一个从第 0 步走到第 64 步的例子

第 32 步：抽取历史并重新预填充

令 I_t 表示环境第 t 步取得的图像，A_t 表示在该处开始生成的动作块。假设每块执行四步，并且历史抽样恰好取得八帧，第一段结束后可以用下列示意表示第二段的起点：

旧窗口结束：清空旧窗口的 KV 上下文
历史图像：I_0, I_4, I_8, I_12, I_16, I_20, I_24, I_28
当前图像：I_32
重新编码所选图像，预填充新窗口，再生成 A_32

历史图像不是八个普通文字 token。“记忆占位”对应的是一组视觉特征位置，经过投影与空间池化后仍可能占多个视觉 token；它既不是自动生成的文字摘要，也不是高层控制器给低层的动作潜变量。

第 36、40 步：追加，而非每次丢掉最旧的一帧

在同一第二窗口内，到 I_36 和 I_40 时继续追加当前观测及动作上下文，复用这一窗口已建立的 KV。I_32 不会因为出现 I_36 就自动被 FIFO 式丢弃。窗口起点所选的历史集合也不是每次规划都平移一次。

因此，“32 到 64 步始终只保留最近八帧，来一帧扔一帧”会误解这条执行路径。它更接近在边界压缩历史、在窗口内部增长的分块上下文。

第 64 步：重新扩大历史覆盖跨度

沿用相同假设，第三窗口可以从更长历史中抽取 I_0、I_8、…、I_56，再加当前 I_64，并重建上下文。抽样间隔增大使有限历史位置覆盖更长时间，但会损失细节。真实索引取决于已有图像数量、步号和整除逻辑；这些序列是帮助理解的条件化例子，不是任意参数下都精确八帧的保证。

论文描述、公开代码与实际测试要分开

压缩视觉特征不等于复用跨窗 KV

原回答还讨论了借助深度、位姿和三维体素压缩历史、保留近端 token 状态的设计。这属于原讨论对论文机制的解释，不能自动当成本次公开推理分支已经执行的事实。此次检查的视觉编码函数中，选定图像经视觉主干、投影及池化形成特征；该函数虽接收相关参数，所读函数体并未据此完成上述三维剪枝。函数签名中出现深度或位姿，不足以证明它们参与了这一步计算。

同理，上下文长度受到窗口控制，不代表程序保存的完整 RGB 历史列表也受到同样的内存上限。检查 GPU KV 和主机图像缓存时，应分别计量。

与双系统导航的区别

StreamVLN 在这里划分的是长短历史和生成上下文；InternVLA 双系统划分的是高层规划与低层持续控制。两者都可能减少昂贵计算，但接口与时间尺度不同。动作块可以减少模型调用，也会使块内的新障碍不能立即通过下一次视觉规划响应，实际部署还需要独立控制与安全机制。

本篇完成了原讨论整理和指定公开代码检查，没有运行模型或测量缓存加速。窗口长度、历史抽样密度、动作块长度怎样影响成功率和反应时间，仍需在同一环境、同一检查点上做对照测试。

一帧怎样变成视觉 token，动作怎样生成

从 patch 到语言模型隐藏维度

后续问题追问“缓存的究竟是什么”。原讨论针对 LLaVA-Video-7B-Qwen2 配置和 StreamVLN 的 SigLIP 编码器给出的链路是：输入 3×384×384 图像，经核与步长均为 14、无补边的 patch 卷积得到 27×27=729 个向量，每个 1152 维。这里保留空间 patch 序列，不是把整张图压成一个分类向量。编码器原配置为 27 层、16 个注意力头；所读加载实现删除最后一层，因此实际保留 26 层，不能直接照配置层数描述运行图。

投影器把 1152→3584→3584，中间使用 GELU；这一步改变特征维度，不减少 token 数。二维双线性池化在该实现中以 stride 2 将 27×27 网格变成 14×14，即每帧 196×3584。因此，八张历史图加一张当前图对应 1764 个视觉向量，再与文字序列组合。<memory>、<image> 是插入入口，不能把它们误读成每张图只占一个 token；它们也不是先把图像转换成文字描述。不同帧使用同一视觉编码器，跨帧信息在后续上下文中交互。

本次核对了公开模型配置与SigLIP 加载实现。这些维度属于该配置与实现组合，换编码器、分辨率或池化代码后需要重新核对，不能当成所有 StreamVLN 版本的常量。

图像特征缓存与注意力缓存不是同一种张量

上述 Qwen2 配置隐藏维度 3584，共 28 层；查询头数 28，KV 头数 4，每头 128 维，前馈中间维度 18944，词表大小 152064。分组查询注意力使每层缓存 K/V 的典型形状为 B×4×L×128，其中 B 为 batch 大小、L 为已缓存序列长度。它与每帧 196×3584 的视觉特征不同：前者服务于逐 token 注意力复用，后者是图像编码结果。RoPE、RMSNorm 和 SwiGLU 也各有作用，不能把整个过程简化成“图片向量相加”。

语言模型头将隐藏向量映射到词表，按因果顺序生成动作符号和停止符。训练中的四动作块格式不等于模型内部有四个固定动作 query 槽；实际解码还受停止、生成长度、解析器与执行循环约束。原讨论中的架构解释属于源码和配置分析，本次未运行该模型测量 token 数、缓存峰值或导航成功率。
