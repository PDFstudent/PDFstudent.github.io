全局规划、指定路线与重规划策略

解释指定路线为何不能只下发终点，怎样从中段接入，以及如何区分资产、规划与执行失败。

全局规划指定路线行为树地图资产

业务要求机器人沿指定通道经过若干位置，但只把终点交给规划器后，它可能走了另一条更短路线。把每个点当独立目标又可能造成反复规划与启停。这说明路线中的顺序和通行走廊也是任务约束，不能在接口中丢掉。

本文从路线如何保存讲到怎样执行，重点解释中途接入、一次规划和定位恢复后的重新接入。它解决的是“走哪条路”的问题；路径变成速度的过程见局部控制器专题。

为什么指定路线不能简化成一个终点

先定义业务约束，再选择资产格式。原始编辑数据、运行生成路径和控制器局部片段需要可追溯，但不必承担相同职责。

目标导航与路线导航

普通目标导航只约束终点，规划器可以选择任意可行路径。指定路线表达业务规定的通行走廊、方向和顺序，路径本身就是任务的一部分。

若把指定路线只转换成终点，规划器可能选择更短但不符合业务的路线。若把每个路径点都当成独立目标，又会造成频繁规划和启停。

路线资产的三层表示

原始路线保存人工标注的有序位姿；运行前可做重采样和平滑，得到连续可执行路径；控制器只消费当前位置附近的局部路径段。

三层数据应分别保存来源版本、坐标系、方向和点间距，避免编辑结果与运行路径混淆。

资产至少记录 map_id、map_hash、frame_id、route_id、version、poses、direction。运行生成物还应记录重采样间距、平滑算法和碰撞校验版本，使路线能够复现而不是只剩一串无来源坐标。

在地图上用带方向的位姿工具记录路径点，比只发布无朝向点更适合路线导航。每个点保存平面位置和航向，可以表达拐弯前后的车体方向。

粗站点、精站点和指定路线应使用不同资产文件，因为字段、校验和执行语义不同。

机器人完成定位后，可以通过遥控沿目标路线移动，在关键位置调用记录接口增量保存全局位姿。

记录工具应支持开始、追加、撤销最后一点、预览、保存和取消，并在保存时校验点间距、重复点和方向连续性。

机器人不在起点时，怎样接入而不走回头路

执行接口需要同时回答何时规划、怎样选择当前段、何时允许重新接入。这三件事共同决定路线是否被稳定执行。

多点导航行为树

多点导航不一定在距离下一个点固定阈值时简单替换目标。实现可能把所有位姿交给规划器生成一条路径，也可能逐段执行。

需要明确行为树使用的是 NavigateThroughPoses 还是自定义路径执行，失败恢复是针对当前段还是整个路线。

固定路线任务通常希望开始时生成路径，执行中不被周期重规划改变。一次规划能保持路线稳定，但定位跳变、人工移动机器人或地图更新后，旧路径可能不再适用。

更合理的规则是默认不周期重规划，只在明确事件发生时触发：定位恢复后位姿变化超过阈值、机器人被遥控移走、路径资产版本变化或控制器请求重新接入。

从当前位置接入路线

机器人不应总返回路线起点。可以把当前位置投影到路线折线，找到距离最近且方向一致的前向弧长位置，从该位置截取到终点的子路线。

不能只选欧氏距离最近点。路线可能折返或相邻段空间接近，需要比较路线切向与机器人航向，排除反向段，并设置最大接入距离。

  1. 将当前位置变换到路线坐标系。
  2. 对每条线段求正交投影和线段内比例。
  3. 计算投影距离、累计弧长和切向方向。
  4. 用距离与方向联合评分。
  5. 选择前向可行候选。
  6. 从投影点拼接剩余路线。
  7. 对拼接处做曲率和碰撞检查。

对线段 p_i→p_(i+1)，投影比例可写为 t=clamp(((x-p_i)·d)/(d·d),0,1)，候选点为 p_i+t·d。评分除横向距离外，还应加入机器人航向与切向夹角、累计弧长是否前向、候选附近碰撞和接入曲率。

折返路线为什么不能只找最近点

考虑两条相距很近但行驶方向相反的平行路段。机器人在第一条向前走时，定位噪声可能让第二条的某个点在欧氏距离上更近。若每周期直接取最近点，当前路线索引就会跳到返程段，后面的控制器即使工作正常，也会追错方向。

因此投影候选还要结合切向方向、历史累计弧长和允许接入距离。对长度为零的重复线段，应先跳过，避免投影公式除以零；对交叉口多个方向都合法的情况，则需要任务进度或指定接入段来消歧。计算出连接线之后，还必须验证连接段的曲率和碰撞，而不能只确认端点安全。

出现导航失败时，怎样区分资产、规划和执行问题

路线点本身正确，还不足以保证任务成功。地图版本、坐标原点、起终点代价和执行能力都可能在后续阶段破坏它。

地图注册

地图 ID 与目录、地图文件和任务资产的关系应由统一注册表管理。站点和路线文件不应重复保存容易漂移的地图 ID。

运行时先用任务中的地图 ID 查注册表，再定位地图目录及其站点、路线资产。这样修改地图编号时不需要同步改多份资产。

规划失败定位

失败可能来自起点或终点落在障碍、起终点超出地图、代价地图未更新、容差过小或坐标变换过期。

日志应分别输出起点代价、终点代价、是否成功投影到自由空间、搜索展开数量和失败阶段，避免只保留“无法生成路径”。

仿真资产要同时包含与真实地图对应的障碍布局、地图注册、站点和路线文件。只复制路线文件而不保持坐标原点和分辨率一致，会让路线整体偏移。

测试至少覆盖从路线起点接入、从中段接入、接近折返段、路线前方有障碍和定位跳变后重新接入。

三类失败不能混写

资产失败包括地图版本不匹配、坐标系错误和路线断裂；规划失败包括起终点代价、搜索无解和容差不足；执行失败包括控制器无法跟踪、动态障碍和定位跳变。三类错误应有独立错误码和证据字段，不能都归结为“导航失败”。

只在目标更新时规划：避免失去抢占能力

普通 Sequence 与 PipelineSequence 的差别

9 月 9 日交接记录了一个重要纠正：减少规划调用次数，不能以丢失目标更新为代价。普通 Sequence 可能停在 RUNNING 的 FollowPath，已成功的规划节点不再被访问；blackboard 的 goal 即使已更新，path 仍可能是旧目标的路径。PipelineSequence 可在后部运行时重新 tick 前置分支，再通过目标变化门控规划。

本轮核对 Jazzy GoalUpdatedController 源码：首次激活、goal/goals 内容变化会允许子节点执行，已经 RUNNING 的子节点会继续执行到结束。因此“一次规划”不是只 tick 一次；比较消息内容也不是直接比较 Action UUID。同目标重发、树复位和失败重试需分别测试。

应沿“收到新 Action → 更新黑板 → 计算新路径 → 控制器接收新路径”验证；Goal accepted 只证明第一层。目标不变但旧路被堵时，还需明确重新规划或停车等待策略。

必经点、整条路径与一次底层搜索不同

NavigateThroughPoses 约束途经目标，点间路线仍可由规划器选择。多点规划请求可以内部逐段搜索并拼接，因此一次请求不等于一次 A*。RemovePassedGoals 修改剩余目标列表，与“到该点才开始规划下一段”不是同一机制；若门控也比较这份列表，删除已通过点可能触发重规划。

直接 FollowPath 交付几何路径，不自动包含全局规划及完整行为树恢复；控制器仍可能偏离、拒绝或跟踪失败。限定通行走廊需要结合区域约束，稀疏点不能保证严格沿线。行为树文件存在、配置为默认和进程实际加载，也是三个不同状态。

从点击点到路径还需要坐标语义

点列应保留 frame、地图身份、单位与顺序；相同 map 名称不能唯一识别地图。非重复点可用 yaw_i=atan2(y_(i+1)-y_i,x_(i+1)-x_i) 构造切向，重复点需另行处理；末端航向独立明确。平面四元数为 z=sin(yaw/2), w=cos(yaw/2)，其余旋转分量为零。

点落在自由栅格不保证车体轮廓或连接段能通过。验证应比较仅终点与显著不同必经通道的路径，再观察实际运动、取消响应及最终停止。关闭客户端不等于取消服务端目标。此补档只覆盖跨日任务中的七个原日期回合，不能据此宣称整个历史任务已读完。

历史补档：路线点的航向从哪里来

自动切线与显式姿态要保留来源

pc-01 的历史交接补充了点选位置与拖动姿态的差别。自动方向可以用 yaw=atan2(y_next-y,x_next-x) 推导，平面四元数为 (0,0,sin(yaw/2),cos(yaw/2))；角度单位是弧度。显式方向则来自用户指定姿态，应验证其有效性，不能被新增后继点时的自动切线重算覆盖。

相邻点重合时方向未定义，末点没有后继时也需明确规则，例如沿用最后一段或要求显式末端方向。同位置改变朝向可能是合法位姿编辑，不能一律当重复点删除。这是交接中的边界推导，未声称具体实现已经支持。可视化的线段切线与姿态箭头也应分开解释。

保存方向不等于每个中间点都会停下对齐

路线编辑负责数据制作，导航执行负责规划、跟踪、取消和结果。二者之间要明确地图身份、frame、单位、点序与姿态含义。保存 yaw、传入规划器、控制器到位对齐，是三个不同承诺。多点规划可在一次请求内完成多个分段搜索，再连续跟踪，不能理解成每到一个半径才启动下一段。

移除更新剩余目标的节点，可能使反馈数量不再递减，即使路径仍在被跟踪。反馈应区分输入目标数、路径进度和任务终态。上层客户端退出也不保证下游取消已生效，需验证取消传播及执行停止。本节来自脱敏交接，主机未直接读取该设备原会话或重跑现场测试。

手动示教路线时，应该记录哪一个位姿

路线坐标要能跨越局部里程计漂移

补充的历史交接讨论问：不开完整导航栈，能否手动移动并记录路线？关键是位姿来源是否已经满足记录器的依赖。若定位模块持续提供有效的 map→odom 与 odom→base，可组合 T_map_base=T_map_odom T_odom_base 得到地图坐标中的机器人位姿；不必为了录点强行启用完整规划和控制链。反之，仅有局部里程计而没有地图对齐，就不能把它当作地图路线。

TF 树中有这条边、查询成功、时间新鲜、数值可信，是不同条件。机器人静止时位姿不变很正常；一直读到旧时间戳却没有新定位则是另一回事。多进程或跨设备的 ROS 通信问题，也需要先检查节点、话题和时间条件，不能直接归因于定位算法。

录点策略会改变路线的可执行语义

记录器至少应明确追加、撤销、清空、保存的状态，区分内存中的路线与已经写入的文件。按位置距离去重能减少静止重复点，却可能删除“同位置、不同朝向”的关键姿态；阈值应与是否记录朝向、是否允许原地转向一起设计。

示教路线是一组带坐标语义的目标，不自动提供避障、碰撞检查或动力学可行性。重放前还需检查当前地图与记录地图是否一致，以及控制端怎样处理点间路径。本节来自采集端的技术交接；发布端未直接读取该设备原始会话，也未重放机器人路线。
