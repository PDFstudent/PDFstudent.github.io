OmTrackVLA：从视频滑窗到训练梯度

追踪 145 帧如何生成 129 个样本、历史 token 如何进入 Qwen，以及小样本训练为何需要均值基线。

VLN实验证据模型机制

两条视频能产生129个样本，却不能当作129次独立跟踪经验。原讨论逐步检查了数据转换、实际张量、梯度和验证误差，并修正过几处只看注释得到的解释。本文按当时的源码阅读与实验记录整理，不把示例数据实验写成官方完整训练复现。

滑动窗口的边界决定标签含义

145 帧为什么变成129个样本

两个 rollout 分别有61与84帧，每个样本需要保留后面8帧，于是分别得到53与76个样本，总计129。全局索引64落在第二个 episode，而非第一个 episode 的第64帧，因此可用历史只有11帧；不能用全局索引推断已经拥有31帧历史。

转换脚本记录的 actions 使用闭区间 j..j+8，长度为9；积分轨迹的第一个点已经执行过一次 dt=0.1 的动作，并非注释所说的原点。Dataset 后续又构造8个路点监督。因此 JSON 中动作长度、积分点数、模型输出8×3是不同层次，检查一个字段的 shape 不能替代整条数据链核对。

历史采样距离为0、2、4…30时，一个完整窗口跨越的是采样间隔，不能将31个索引机械地解释为31秒。缺少历史时，所读训练 Dataset 用当前帧 coarse 特征补齐，而推理分支使用最早可得的历史帧补齐；这是训练/推理差异，尚不能仅凭代码认定它对成功率有多大影响。

从图像到语言模型的序列

DINOv3 的384维和 SigLIP 的1152维特征拼接成1536维视觉表示。历史每帧做2×2池化得到4个 coarse token，当前帧做8×8池化得到64个 fine token。31帧历史共有124个视觉 token；另插入31个历史 TVI 和1个当前 TVI，故历史段155、当前段65。TVI是独立插入的时间/视图/类型 token，不是把同一向量分别加到四个视觉 token 上。

一次实际 batch=2 的前向记录为：7个语言 token＋155个历史 token＋65个当前 token＋1个 ACT=228。文本长度会变，228不是固定常数。时间索引是序列位置，不自动包含真实秒数；默认路径的角度投影参数虽然存在，却未启用，不能把参数存在写成输入已使用。

缓存保存为 fp16 不表示视觉前向也在 fp16 运算。另一个容易误读的配置是“batch=8”：所检查缓存实现内部逐图编码，因此声明参数不等于实际执行批量大小。

冻结主干为何仍需要反向图

实验中 Qwen 约5.96亿参数被冻结，没有参数梯度；投影层、ACT、TVI和动作头仍取得非零梯度。冻结参数只是令主干权重不更新，不等于可以对整个主干包上 no_grad：训练前端投影时，梯度仍要穿过冻结的主干回到输入。

可训练视觉投影 → 冻结 Qwen 运算 → 可训练动作头 → loss
       ↑                 反向链仍需保留              |
       └───────────────────────────────────────────┘

路点的 masked MSE 应只统计 valid 点，并说明 x、y 与 yaw 混合了长度和角度单位。对三维误差直接开平方不能统一称为“米制轨迹误差”。正式训练的损失权重与单 batch 调试里的原始 MSE 也不能混用。一次 AdamW 后 loss 上升可能涉及学习率、训练/评估模式等因素，不能直接判成梯度无效。

loss 大幅下降后，还要比较什么

两样本20步实验从0.00882528降至0.00010993，说明可以记忆；53个训练样本、76个验证样本的划分仍来自同一场景和相同指令，只能检查有限的跨 episode 表现。一次验证得到 ADE 0.077410m、FDE 0.107121m、yaw MAE 2.6988°；零运动 ADE 0.121162m，训练集平均轨迹 ADE 0.063091m。模型胜过零运动却输给简单均值，说明不能仅凭 loss 或漂亮的轨迹图宣称理解了视觉。

后续早停模型 ADE 0.072259m、FDE 0.113748m、yaw 2.2172°：某些指标改善而 FDE 退步，且均值基线的 ADE 仍更好。用于选择早停点的集合已经是验证集，不能再称为未使用的最终测试集。

打乱整组当前帧、历史帧或两者时，ADE分别上升约3.35%、3.25%、8.14%；视觉置零上升约130.58%。这支持当前输出依赖视觉输入，却不能证明学到了正确的身份或时间顺序：同 episode 的相邻窗口高度相关，打乱幅度有限；全零又可能是分布外输入。需要跨场景、不同目标身份和更严格时间干预的闭环实验才能继续归因。

场景资源齐全，为何还不能直接训练

从资产、episode 到监督样本

后续讨论又区分了“已经下载场景”与“已经拥有图像—动作监督”。场景模型、可行走网格、人物与机器人资源描述仿真环境；episode 描述起点、目标身份和任务条件。任务定义文件即使名为 train，也不意味着它就是模型训练 Dataset 可以直接读取的监督样本。

实际依赖链是：

场景与角色资产 + episode任务定义
  → 由控制器运行仿真
  → 视频/图像、逐步动作与状态记录
  → 时间对齐、抽帧、轨迹标签和样本索引
  → 可选视觉特征缓存
  → 训练、独立评测与闭环验证

因此，资产包中的文件数量不能换算成训练样本数；同一个场景可以生成许多轨迹，一条轨迹又可切出高度相关的滑窗样本。数据准备应逐层检查实际内容和接口，不能用“场景文件无缺失”推断“拥有完整官方训练集”。

预处理可能主要使用 CPU，视觉编码和模型训练通常使用 GPU；仿真是否需要 GPU 图形组件又是另一项条件。资源分配应依据具体阶段，而不是把整个链路一律当成同一种训练任务。

全量数据与全参数训练是两条轴

使用所有可用样本描述数据范围，更新全部权重描述参数范围。二者可以独立选择：大量样本仍可冻结主干，小样本也可能全参数更新。使用预先生成的视觉缓存，通常意味着当前训练不反传到产生缓存的视觉编码器。

同一项目的不同入口可能存在不同冻结默认值，应记录最终生效配置以及实际有梯度、被优化器更新的参数。判断全量训练是否就绪，还需检查验证集配置、恢复训练是否使用保存的起始 epoch、最后一步是否强制保存 checkpoint，以及输出是否位于持久化位置。入口能解析或文件通过语法检查，只是运行前证据。

仿真检查成功，为何仍不能证明轨迹有效

episode 与控制器各自定义什么

episode 是一次任务实例，决定场景、目标与初始条件；控制器或模型根据观测产生动作。用依赖仿真真值的规则控制器采集轨迹，与加载学习模型权重进行推理，是不同实验。GTBBoxAgent 这类规则控制器可用于验证采集链路，但其真值信息条件不能悄悄搬到部署模型的能力说明中。

原讨论中的历史检查报告描述了一个有限结果：五步仿真完成初始化、步进和图像输出，但机器人位置未发生变化。这个例子支持“运行链路可工作”，不支持“已经学会或完成跟随”。该早期记录当时没有后续完整 episode 结果；11 月 2 日的后续讨论另有完整运行报告，见下文，两次实验不可混为同一结果。

用可观测量逐层验证

在扩大采集前，需分别检查目标身份是否绑定正确、目标是否运动、动作是否非零且有效、机器人位移是否符合预期、碰撞及终止原因是否正确记录，以及视频与动作时间是否对齐。进程成功退出、报告成功和轨迹可用是三个层次。没有有效运动可能来自目标未绑定、规则触发条件未满足等，必须依据记录继续诊断，不能只靠最终状态归因。

失败轨迹有诊断价值，应保存失败原因、有效区间和质量标记；它不会因为被保存就自动成为合格专家监督。早期记录未取得完整采集结果；后续单条运行已有失败报告，但完整跟随、长时稳定性和训练收益仍需分别验证。

用资产身份闭合证据链

代码及配置固定到提交，环境固定到镜像身份，输入固定到数据版本，并保存解析后配置、日志、checkpoint 和评测产物。源码版本库、镜像、场景数据、权重和运行输出各有职责，不宜把整个实验目录打包混为代码。

独立评测必须加载刚训练出的权重；另一个官方 checkpoint 的仿真表现不能替代本次训练效果。环境迁移及 CUDA/EGL 的分层验证见 Conda 与容器渲染排障。

后续训练入口与完整轨迹报告：不要沿用旧实验的冻结结论

视觉缓存、Qwen 更新与新规划头分别说明

11 月 2 日的后续原讨论说明：该训练入口读取预计算视觉特征，不更新视觉编码器；视觉投影、时间表示、Qwen 和轨迹头参与更新，且没有采用 LoRA。基础 Qwen 初始化加上新投影与规划头，并不等于加载了官方已训练好的完整 OmTrackVLA。这与前文冻结 Qwen 的早期诊断实验是不同入口与配置，不能用其中一次概括整个项目。

监督仍是未来 8 个平面路点及朝向，优化轨迹误差而不是聊天生成。小样本可以执行全参数更新，但流程执行成功不能替代样本充分性与泛化证据。评测初始化与 checkpoint 覆盖的顺序见权重与离线评测。

进程正常结束与跟随失败可以同时成立

后续助手报告了完整单条采集尝试：程序结束并保存了视频、逐步记录和结果，但 episode 因丢失目标提前结束。该报告支持“采集和保存流程执行过”，不支持“专家轨迹有效”。本轮没有重新读取内部运行产物，故不把历史报告写成独立复测，也不公开平台运行明细。

用户观察到视频跳动，助手尚未看到视频时提出控制步间位移过大的可能性。若每个控制步骤只存一帧，采样间隔可能影响视觉连续性；但这只是待验证解释，仍需逐帧对照动作、时间戳与位姿，不能认定为跳动或跟丢的根因。

数据数量必须带上数据类型和项目范围

某份示例数据的训练/验证条数不代表本地全部资料。后续讨论将其他项目的轨迹数据库、当前项目的 episode 定义以及已转换的监督样本重新分开。不同任务的动作、观测和标签语义不一致，不能因为都叫轨迹就直接替换；同场景无重叠帧也不能证明跨场景泛化。

采集后的质量检查应包括视频与动作记录对齐、有效运动、终止原因、划分隔离及转换可读性。采集尝试数既不是成功轨迹数，也不是最终训练样本数。只有真实产物经过筛选和转换，并被训练读取，才能建立完整上下游关系。

补充：轨迹切窗与视觉缓存的边界

一条轨迹为什么能产生许多样本

新增问题关注轨迹数与样本数的差别。原讨论所述转换对当前索引 j 取 j 到 j+8，包含两端共 9 条动作，再处理成模型需要的 8 个目标轨迹点；历史图像最多取前 31 帧。对 N 条完整动作记录且该规则无额外筛选时，可选索引数为 max(0,N-8)。设置名 horizon=8 不能直接推断切片只含 8 条动作，应检查端点和加载器的处理。

教学例子中，N=100 可得到 92 个重叠窗口。这不等于 92 次独立采集，相邻窗口共享大部分图像和动作。应先按 episode 或场景划分，再切窗；否则相邻窗口进入训练和验证两边，指标会偏乐观。具体实现若还过滤碰撞、目标丢失或无效几何，最终样本数会进一步下降。

固定编码器允许缓存，动态条件限制复用

当 DINOv3 与 SigLIP 权重和图像预处理固定时，同一图像的两类特征可先计算再复用。若每张图分别保存两个特征文件，M 张图对应 2M 个文件只是存储约定，不表示所有格式都必须如此。验收还应检查每个样本引用是否存在、形状与数值是否符合消费接口。

更新视觉编码器或改变增强、裁剪、分辨率，会改变特征；缓存身份必须随之变化。闭环产生新画面，也需要对新观测编码。冻结视觉编码器与冻结语言主干是独立选择，不能根据“使用缓存”推断整个模型不训练。更细的梯度边界见 DualVLN 专家监督与冻结主干。本节来自新增原问答；未重新运行其转换或缓存脚本。
