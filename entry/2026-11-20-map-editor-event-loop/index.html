地图编辑器卡住或空白：事件重入、缓存与保存边界

串联选择回调重入、画布布局时序和原始栅格编辑，解释窗口打开、渲染正确与文件保存的不同证据。

技术复盘验证边界

点击树节点后界面卡住，恢复后窗口能打开却没有地图，问题不一定在同一层。11 月 19 日交接包含两次不同修正：选择事件重入造成重复重绘，画布布局尚未完成又导致错误尺寸被缓存。应分别验证事件流、几何尺寸、图像内容与文件状态。

为什么堆栈停在绘图函数，不等于绘图库坏了

程序修改选择也可能重新触发选择事件

Treeview 的选择回调如果再次设置相同选择，可能重新触发回调；每次又重建节点、缩放大图或绘制标记，就形成事件循环和昂贵的重复工作。中断时堆栈落在绘图函数，只说明采样时正在绘图，不能直接确定根因。

先比较新旧选择，相同则返回；再区分用户选择与程序同步，并对必要的程序更新建立重入保护。整理示意如下，实际事件库仍需核对自身触发语义：

def on_selection(candidate):
    if syncing or candidate == current_selection:
        return
    apply_selection(candidate)

保护状态需在异常路径也释放；仅捕获 KeyboardInterrupt 不会消除重复事件。底图缩放缓存与轻量标记更新应分离，避免每次选择都重新处理整张地图。历史回执报告切换与退出检查通过，本轮没有运行该 GUI。

窗口打开只验证启动链的一部分

源码入口、安装后的入口、终端环境和图形会话是不同条件。某环境中窗口打开，不能证明另一环境启动正常，更不能证明画布已经绘出地图。来源中的启动失败问题和后续助手回执属于两个真实回合，归档保留各自身份，没有虚构同回合回答。

为什么地图可能被永久缩成一个像素

初始化尺寸可能只是布局前的占位值

如果首次 fit 在容器只有占位尺寸时执行，缓存可能保存几乎不可见的图像；后续窗口变大但没有使缓存失效，就继续显示错误结果。图像文件可以完全正确，问题仍发生在布局与渲染时序。

应在布局完成并取得有效尺寸后重算适配。缓存键至少区分图像版本、画布尺寸和缩放；尺寸改变时触发失效，但对频繁 Configure 事件合并处理，避免“重绘改变布局、布局又触发重绘”的循环。历史报告称修正后可显示地图，这与上一节的启动检查是独立证据。

拖动和笔刷应回到原始网格坐标

屏幕像素受到缩放和平移影响，不能直接当原始地图格坐标。编辑操作应经逆视图变换落到原始栅格，并保持图像类型、尺寸、分辨率和原点。一次连续笔画作为一个撤销单元，避免每个鼠标采样点都要求用户单独撤销。

这也解释为什么“预览看起来擦掉了”不够：显示缓存可能变化，原始网格尚未修改，或修改尚未持久化。相关的物理笔刷尺度与运行时加载见代价地图专题。

保存与恢复应验证到哪个层次

原子替换不能自动覆盖多文件一致性

写入前检查磁盘版本是否仍为开始编辑时的版本，防止覆盖并发更新；先保存到临时文件并校验，再按既定机制替换目标。单文件原子替换防止看到半个文件，但地图图像、YAML 与相关资产同时变化时，还需一致的版本切换或恢复方案，不能把多次单文件替换称为一个完整事务。

撤销后文件哈希未变，只支持测试期间未改变磁盘字节；它不证明断电、写入失败或多文件恢复路径已经验证。预览可以单独生成并标注来源版本，不应为刷新显示而覆盖原始资产。

哪张图参与导航，要沿引用关系判断

检查地图 YAML 的 image 引用和实际启动参数，而不是按 PNG、PGM 扩展名判断用途。在线增量快照与优化后重投影地图可能拥有相同尺寸、原点和分辨率，内部占据内容仍不相同。预览、运行地图和源数据应明确角色与版本，不能形成“某格式一律只是预览”的规则。
