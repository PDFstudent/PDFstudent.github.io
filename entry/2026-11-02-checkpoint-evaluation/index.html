评测到底加载哪份权重：checkpoint、NPZ 与有效点指标

说明基础模型与完整 checkpoint 的加载顺序，并用有效点掩码计算轨迹误差，区分离线指标与闭环成功。

PyTorchcheckpointNPZ轨迹评测

评测同时需要基础模型目录和训练 checkpoint，容易被理解为两个模型一起预测。原讨论进一步追问“权重什么时候替换”和“predictions.npz 怎样查看”。关键是区分构建模型需要的文件、内存中的最终参数和保存后的预测数据。

基础文件负责构建，checkpoint 决定最终参数

替换发生在首次预测之前

一种常见入口先读取配置、tokenizer 和基础权重，构造语言主干、视觉投影与轨迹头；随后把完整训练状态写进同一个模型。原讨论报告的关键调用为：

model.load_state_dict(obj['model_state'], strict=True)

它更新内存中的参数与持久化 buffer，并不修改磁盘上的基础权重文件。随后移动到计算设备、调用 eval()，在不需要梯度的上下文中评测。eval() 与禁用梯度作用不同：前者切换相关模块行为，后者控制自动求导记录。

strict=True 能帮助发现参数键不匹配，结构或张量形状不兼容通常也会报错；它不能证明 checkpoint 具有正确来源，亦不能发现语义错误但形状相同的数据配置。还需记录输入文件哈希、代码与配置身份、实际加载路径的角色，以及评测使用的划分。

完整参数、适配器与恢复训练不能混淆

上述覆盖成立的前提是 checkpoint 包含该模型所需的完整状态。只保存 LoRA 或部分模块时，还需明确基础权重身份及相应加载方法，不能照搬“全部覆盖”的解释。仅恢复推理权重也不等于恢复训练：优化器、学习率调度器、训练步数和必要随机状态是否保存，要按恢复目标检查。

把配置、tokenizer、训练后参数和预处理约定一起导出，可减少评测对旧基础目录的依赖。但模型资产打包完整，只证明加载条件较齐全，不证明模型已经取得有效收益。

训练完成需要参数变化和产物身份两类证据

配置、一次运行和产物是三个对象

训练配置可以反复执行，每次执行应有自己的日志和输出。日志写出“成功”后，还应检查确实发生优化步骤、最终 checkpoint 存在且可加载；独立评测应读取这份产物，而不是同目录中另一份旧权重。

原讨论的助手报告过训练结束、严格加载和训练产物哈希对应；本轮仅获得该讨论，没有独立读取其运行文件，因此将其保留为历史报告，省略内部平台与指标明细。它支持讨论加载链路，不能替代本轮训练实验或模型能力证明。

NPZ 怎样还原预测，而无需再次加载模型

先读形状与掩码，再画曲线

示例文件约定 pred 与 gt 为 N×H×3，最后一维为 x、y、yaw；valid_mask 为 N×H。N 是样本数、H 是最大预测长度，填充位置不参与评测。可选图像引用只是路径字符串，文件不因此包含原图。以下是据原讨论整理的通用检查代码，使用自己的输出文件：

import numpy as np
import matplotlib.pyplot as plt

with np.load('predictions.npz', allow_pickle=False) as data:
    pred = data['pred']
    gt = data['gt']
    valid = data['valid_mask'].astype(bool)
    assert pred.shape == gt.shape
    assert pred.ndim == 3 and pred.shape[-1] == 3
    assert valid.shape == pred.shape[:2]
    assert np.isfinite(pred[valid]).all()
    assert np.isfinite(gt[valid]).all()
    candidates = np.flatnonzero(valid.any(axis=1))
    if len(candidates) == 0:
        raise ValueError('No valid trajectory points')
    i = int(candidates[0])
    p, g = pred[i][valid[i]], gt[i][valid[i]]
    plt.plot(g[:, 0], g[:, 1], 'o-', label='reference')
    plt.plot(p[:, 0], p[:, 1], 'x--', label='prediction')
    plt.axis('equal')
    plt.legend()
    plt.grid(True)
    plt.show()

数值曲线不需要重新加载 Qwen。相等坐标尺度避免图形失真；曲线只比较 XY，不表示朝向正确。若文件把字符串存成对象数组，应先核对导出格式，不能为了读一个附加字段就无条件启用 pickle。

三种“平均误差”并不相同

令 m_it 表示有效点，p_it、g_it 为预测与真实 XY，e_it=||p_it-g_it||₂：

E_points = sum_i,t m_it e_it / sum_i,t m_it
E_samples = mean_i [sum_t m_it e_it / sum_t m_it]
FDE = mean_i e_i,last_valid(i)
Hit(tau) = mean_i 1[e_i,last_valid(i) <= tau]

对没有有效点的样本应单独报告数量并定义处理规则，不能静默把它当零误差。E_points 按点加权，E_samples 每条样本等权；长度不同时二者会不同。末点必须取最后一个有效点，不能机械使用固定 H-1。

例如两条示意轨迹分别有 1 和 3 个有效点，逐点误差分别全为 0 与 2，则按点平均是 1.5，按样本平均是 1。这个人为例子说明分母差异，不是原实验结果。tau 的单位与数据坐标一致，未核对单位前不直接标“米”。

若要评估 yaw，应使用周期角差，避免正负 π 附近产生整周误差。把 XY 与角度一起求均方误差后开根号，也不能称作纯米制误差。

离线误差低，为什么仍不能声称跟随成功

独立划分与基线决定结论强度

终点误差落在阈值内的比例只描述离线样本，不是机器人实际跟随成功率。相邻滑窗高度相关，同场景不同 episode 也未必代表跨场景泛化；训练前模型、零运动和平均轨迹基线能帮助判断是否取得有意义增益。

闭环执行还会改变后续观测分布，并受到碰撞、延迟、目标丢失及控制误差影响。进一步验证需要策略真实交互后的任务指标。数据与梯度背景见 OmTrackVLA 数据训练专题。

补充：流水线连线与真实产物传递

顺序正确不代表模型身份正确

训练成功后才执行评测，只解决运行依赖。评测若仍引用固定的旧 checkpoint，流程可以正常结束，却没有评估本次训练。应使用上游输出绑定的输入位置，并核对训练报告与评测加载文件的哈希、更新步数和数据身份。

原问答还区分规则控制器生成训练轨迹与学习策略闭环执行，两者的成功率不能互换。程序正常结束只说明执行完成，目标丢失、过早停止或碰撞应进入任务指标。已有验证集若只来自少数轨迹的重叠窗口，也不足以证明跨场景泛化。本节省略内部运行数字，保留为原讨论结论；本轮未重新运行模型。
